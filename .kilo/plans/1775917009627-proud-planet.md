# 邮件发送优化计划

## 问题诊断

| 问题 | 原因 | 影响 |
|------|------|------|
| HTML 在部分设备以附件形式显示 | 使用 `multipart/related` MIME 结构 + CID 内嵌图片，某些邮件客户端（尤其是旧版 Outlook、部分 Android 邮件应用）不支持渲染 | 用户看到的是附件而非渲染好的邮件 |
| 图片加载缓慢 | `safevault_icon.png` 文件大小为 **327KB**，作为邮件内嵌图标严重过大 | 邮件打开慢，消耗用户流量 |
| 部分客户端兼容性差 | 没有纯文本（text/plain）备选内容 | 不支持 HTML 的客户端无法显示任何有意义的内容 |

## 优化方案

### 1. 制作优化版邮件图标（解决加载慢问题）

**当前：** `safevault_icon.png` (327KB) — 严重过大
**已有：** `safevault_icon_small.png` (586 bytes) — 分辨率太低

- 使用 `safevault_icon.png` 原图，通过压缩工具（如 TinyPNG/Sharp）生成一个优化版
- 目标：尺寸 90x80px 左右（邮件模板中实际显示尺寸），文件大小 5-10KB
- 输出文件名：`safevault_icon_email.png`
- 放置于 `src/main/resources/static/images/` 目录

### 2. 图片改用外部 URL 引用（解决附件问题）

**文件：** `src/main/resources/templates/email/verification-email.html`、`password-reset.html`

- 将 `<img src="cid:safe-vaultIcon" ...>` 改为外部 HTTPS URL 引用
- URL 格式：`{baseUrl}/static/images/safevault_icon_email.png`
- 在 `EmailService` 中将 `baseUrl` 传入模板替换（新增 `{{baseUrl}}` 占位符）
- 设置合理的 `alt` 和 `width`/`height` 属性

**优点：**
- 消除 `multipart/related` 结构，从根本上解决附件显示问题
- 邮件体积从 ~330KB 降至 < 5KB
- 图片可被浏览器/邮件客户端缓存，后续加载更快

**风险与应对：**
- 用户离线时看不到图片 → 已有文字 "SafeVault" 在 `<h1>` 标签中，不影响功能
- 服务器需处理静态资源请求 → Spring Boot 已默认提供 `static/` 目录的资源服务，需确认安全配置放行

### 3. 移除 Java 代码中的 CID 内嵌逻辑

**文件：** `src/main/java/org/ttt/safevaultbackend/service/EmailService.java`

- 移除 `sendVerificationEmail()` 中的 `helper.addInline("safe-vaultIcon", ...)` 代码块（第 56-63 行）
- 移除 `sendPasswordResetEmail()` 中的 `helper.addInline("safe-vaultIcon", ...)` 代码块（第 127-134 行）
- `MimeMessageHelper` 构造函数改为 `new MimeMessageHelper(mimeMessage, "UTF-8")`，不再需要 `true`（multipart）

### 4. 添加纯文本备选内容

**文件：** `src/main/java/org/ttt/safevaultbackend/service/EmailService.java`

- 使用 `MimeMessageHelper(mimeMessage, true, "UTF-8")` 保持 multipart 模式（用于 alternative）
- 调用 `helper.setText(plainText, htmlContent)` 同时设置纯文本和 HTML 内容
- 纯文本内容使用已有的 `verification-email.txt` 模板
- 密码重置邮件同样添加纯文本版本（需新建 `password-reset.txt` 模板）

### 5. 确认静态资源可公开访问

**文件：** 检查 `SecurityConfig` 或相关安全配置

- 确保 `/static/images/**` 路径不需要认证即可访问
- 如果有安全拦截，需要添加白名单规则

## 修改文件清单

| 序号 | 文件 | 修改内容 |
|------|------|---------|
| 1 | `static/images/safevault_icon_email.png` | **新建** — 从原图压缩生成优化版图标（5-10KB） |
| 2 | `EmailService.java` | 移除 CID 内嵌逻辑；添加 `baseUrl` 到模板占位符；添加纯文本备选 |
| 3 | `verification-email.html` | `cid:safe-vaultIcon` → `{{baseUrl}}/static/images/safevault_icon_email.png` |
| 4 | `password-reset.html` | `cid:safe-vaultIcon` → `{{baseUrl}}/static/images/safevault_icon_email.png` |
| 5 | `templates/email/password-reset.txt` | **新建** — 密码重置邮件纯文本模板 |
| 6 | 安全配置（如需要） | 放行 `/static/images/**` 资源的匿名访问 |

## 预期效果

- 邮件体积从 ~330KB 降至 < 5KB（纯 HTML，不含图片二进制数据）
- 不再出现 HTML 以附件形式显示的问题
- 图标通过外部 URL 加载（5-10KB），可被缓存，后续几乎瞬时
- 不支持 HTML 的客户端也能看到纯文本验证链接
